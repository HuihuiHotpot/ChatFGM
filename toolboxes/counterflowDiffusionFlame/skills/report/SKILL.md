# Report

## Inputs

- 当前算例的 `0-caseDict/caseDict`，包括算例目标、相关阶段的设置与记录，以及已确认的报告要求（如有）。
- 可供本次报告使用的已有产物（如有）。

## Execution

### 1. 确定报告范围和设置

用户已明确报告要求时，按其要求确定相应的范围和设置。对尚未确定的部分，根据算例进展和已有产物拟定方案。确定报告范围时，明确要覆盖的工况、阶段和章节，以及各节需要回答的问题。将拟定的方案向用户说明，请用户确认。

通过 [case-dict](../case-dict/SKILL.md) 将已确认的设置写入 `report.title`、`report.language`、`report.outputFile` 和 `report.sections`。

### 2. 整理所选章节的材料

根据 `report.sections` 中本次确认的章节和内容要求，逐节整理所需材料。从 `caseDict` 获取算例目标、设置和已记录的判断，从执行记录和实际产物核对完成范围与结果。根据章节内容，按需查阅机理核验记录、求解配置、剖面和后处理结果、制表产物及验证报告。

取材时也考虑各阶段预设步骤之外的后处理结果，以及用户另行提供的数据和图表。可从 `caseMeta.notes` 查找相关后处理所用的数据、处理内容和保存路径。核对结果的来源、对应工况和处理方法后，将与本次报告有关的内容纳入相应章节。

#### 选取图表

先明确本节要说明什么，再选取能解释关键现象、体现工况差异或支撑结论的图表。根据报告目标和已有结果选择工况、剖面和变量。需要比较多条剖面时，可将同一变量的曲线合在一张图中。涉及用表判断时，兼顾有代表性的结果和会改变判断的偏差。

#### 准备选定的图表

已有合适的静态图时直接使用。需要嵌入算例目录外的图片时，将选用的图片复制到报告的配套图表目录，并注明原始来源。图表只在 HTML 中展示时，先在页面中确定要引用的内容，再用对应数据绘制报告所需的静态图。

- **火焰面查看器。** 根据选定的结果集，通过对应清单定位 HDF5 剖面，按选定的横坐标和变量绘图。
- **先验验证报告。** 从 `validation_results.json` 读取所选工况、参考剖面和变量的参考值、查表值、残差及误差指标，按报告所需内容绘图。只有 `validation.html` 时，可使用其中嵌入的验证数据。

重绘时沿用原结果的坐标定义和单位。记录所用图表的工况、剖面、变量和来源，供正文引用和交付核对。部分工况采用了不同设置或结果经过重做时，结合执行记录和 `intent.decisionLog` 核对所引用产物的来源及对应设置。

缺少支撑所选章节的材料时，说明缺项及其影响，并提出补做上游工作或调整报告范围的建议。涉及补做或调整时，按 `case-dict` 和对应阶段的规则处理。

### 3. 编写正文

按 `report.language` 和 `report.sections` 中确认的要求编写正文。围绕各节要回答的问题，说明实际完成的工作、主要发现及其对算例目标的意义。涉及用表判断时，写明表能否用于本次目标、适用范围及主要依据。已有重做建议时，说明原因和建议从哪一步开始。

将选定的图表放在相关讨论附近，在正文中说明图表支持什么判断。图注注明理解图表所需的工况、剖面或变量，以及图表来源。用相对于报告文件的路径嵌入图片。引用本地结果文件时，注明其在算例中的路径。需要查看完整曲线或交互细节时，注明原交互报告的路径，供读者从 ChatFGM 工作台的文件树打开。

#### Markdown 公式格式

独立公式从行首开始，单独占一行。公式与两侧的 `$$` 之间不留空格或换行。

$$Y_c=\sum_i w_iY_i$$

行内公式写在正文中，前后各用一个 `$`。例如，用 $Y_c$ 表示进度变量。

## Result Verification and Handoff

将 Markdown 报告保存到 `report.outputFile`，在 ChatFGM 工作台中打开并核对以下内容。

1. 报告标题、语言、章节和保存路径与 `caseDict.report` 中确认的设置一致，各节覆盖了约定的内容。
2. 正文中的工况、计算设置、数值和单位与所引用的记录及产物一致。涉及用表判断时，核对结论、适用范围和依据是否对应本次引用的验证结果。
3. 图表和公式在 ChatFGM 工作台中正常显示，报告中的引用路径指向正确的文件。

核对通过后，交付报告和配套图表，向用户说明报告路径、覆盖范围和主要结论。报告设置有已确认的变更，或编写过程中形成了新的重要决定时，通过 `case-dict` 更新相应记录。
