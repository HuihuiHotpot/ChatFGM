# Case Dict

## When to Use

- 初始化新算例，或需要补全、调整已有算例的设置时。
- 准备进入或继续某个阶段，需要核对该阶段所需的设置是否明确、上游产物是否齐备且适用时。
- 需要维护待确认事项、主要假设、已知限制、重要决策或错误记录时，或需要记录阶段启动、交付完成和旧交付失效时。
- 需要核对或解释 `caseDict` 中的设置或记录，或说明某个字段的含义、当前取值和填写方式时。

## What to Read First

- 遵循当前工具箱目录下的 `AGENTS.md`。
- 处理具体算例时，读取该算例目录下的 `0-caseDict/caseDict`。
- 初始化算例或核对字段结构、默认值时，查阅工具箱目录下的 `standardCase/0-caseDict/caseDict`。
- 填写或解释字段、检查阶段准入条件、维护算例记录时，查阅本 skill 目录下 `references/case-dict-field-guide.md` 的相关部分。

## Invariants

- 沿用用户已明确的设置。新增或调整设置须有明确依据。已确认的方案需要变更时，经用户确认后再写入。标准模板中的默认值适用于本次任务时，可以直接使用。
- 不猜填缺失的关键参数。当前步骤所需且必须由用户确认的事项，记入 `intent.openQuestions`，并向用户确认。
- 按标准模板的字段结构和单位约定填写。确需记录的算例特有设置，若现有字段无法表达，可暂存于 `extensions`。
- 阻塞错误解除前，不执行依赖受影响设置或产物的步骤。
- 算例内文件使用相对于算例根目录的路径，外部源文件按实际位置记录。
- 临时执行的命令和终端会话中的临时变量无需写入 `caseDict`。
- 修改后检查字典语法和相关字段之间的一致性，确认设置与已确认的方案相符，过程记录与实际执行情况相符。

## Standard Workflow

用户要求开始或继续执行算例流程时，按以下步骤处理相关设置、确定阶段并检查准入条件。

1. 读取用户请求，按 `What to Read First` 查阅当前算例和所需资料。本次请求要求初始化、补全或修改算例，或要求执行需要更新算例设置的任务时，将用户已明确或确认的新增和变更设置写入 `caseDict`，并检查改动。
2. 根据用户目标，结合 `caseDict`、执行记录和已有产物，确定当前任务要进入或继续哪个阶段。
3. 对照字段指南的 `Stage Entry Conditions`，检查当前任务所需的设置和上游产物是否满足该阶段的准入条件，以及是否存在影响当前任务的阻塞错误。
4. 阶段准入条件尚未满足时，按缺项处理。
   - 缺少需要用户提供或确认的信息时，询问当前阶段推进所需的事项。收到答复后，将确认的信息写入 `caseDict`，检查字典改动，再复查阶段准入条件。
   - 缺少可用的上游产物或存在阻塞错误时，说明原因并建议先补齐哪些产物或处理哪些问题。处理完成后，再复查阶段准入条件。
5. 阶段准入条件满足后，交由对应阶段 skill。由该 skill 根据用户目标和实际进度确定具体子步骤、检查其准入条件，并按用户确认的范围执行。实际启动某个执行阶段时，按字段指南更新 `workflowState`。
6. 执行结束后，根据实际产物和检查结论更新算例记录。确认某阶段在当前算例范围内的交付已完成后，将其写入 `extensions.completedWorkflowStages`。继续同一阶段时，由对应阶段 skill 判断后续子步骤。需要进入其他阶段时，从第 2 步重新定位。用户补充设置或调整任务时，先按第 1 步处理本次请求。

重做或调整设置时，核对受影响阶段的已有产物。确认旧交付失效后，从 `extensions.completedWorkflowStages` 移除受影响的阶段。重新核验交付完成后再恢复记录。具体字段约定见字段指南。

## Output Requirements

- 核对或解释 `caseDict` 时，直接回答用户的问题。
- 实际修改 `caseDict` 后，简要说明更新了哪些设置或记录。变更影响后续工作时，说明具体影响。
- 仅提供修改建议时，说明建议改什么、为什么改，并明确尚未写入 `caseDict`。
- 用户仅要求核查阶段准入条件时，对照字段指南检查，说明是否具备准入条件，并指出具体缺项或阻塞原因。
